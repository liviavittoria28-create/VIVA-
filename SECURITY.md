# Política de segurança

## Reportar uma vulnerabilidade

Não abra issues públicas para vulnerabilidades. Envie um relato privado ao responsável pelo projeto, com:

- descrição do problema e impacto;
- passos para reproduzir;
- versão ou commit afetado.

Responderemos o mais rápido possível, sem prazo garantido enquanto o projeto estiver em fase inicial.

## Diretrizes

- Nunca publique `service_role`, senhas, chaves ou tokens.
- Use apenas `anon key` no front-end, sempre protegida por RLS.
- Dados de teste devem ser fictícios.
- Consulte [docs/14-SEGURANCA-E-LGPD.md](docs/14-SEGURANCA-E-LGPD.md).
